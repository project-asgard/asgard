Detailed Description

Functions
The PDE term coefficients, sources, initial and boundary conditions must be defined by functions, e.g., y = f(x). ASGarD uses std::function with many different signatures to handle different cases. The std::function approach allows ASGarD to be compiled as a library and work with user provided definitions after the installation, sometimes this is referred to as having an "open" or "extensible" set of types and functionality. The C++ std::function uses v-tables and polymorphic jumps with performance overhead and is mitigated by using "batch" calls, e.g., calling f(x) for a set (vector) of points, as opposed to making a separate v-table jump for each quadrature point in each finite element cell.
Inputs and const correctness
Most of the functions signatures use std::vector with either float or double precision user provided functions should never resize the vectors or violate const-correctness, e.g., by modifying the entries of vectors marked as "const". All vectors and arrays will be pre-allocated to the correct size.
Naming conventions
Function type names that start with "s" relate to a single-dimensional or scalar context, while "md" indicates multidimensional context, i.e., all dimensions defined in the problem and set in the asgard::pde_domain. Suffix "_f" indicates an additional input field, e.g., F(x, y) vs. F(x, y, f(x, y)). Having "mom" in the name indicates moment dependence and the asgard::momentset will be passed into all function calls. The "gpu" indicates that all arrays/pointers relate to data on the GPU device.
GPU context
The GPU context requires either CUDA or ROCM to be enabled in ASGarD. The function signatures use "raw arrays", e.g., "double x[]", as to avoid forcing the use of custom containers.

Vector function, computing fx = F(x), no time-dependence.

Represents a single-dimensional function that is "fixed" in time.

On entry, x is a set of quadrature points within the domain of some direction.

On exit, fx must contain the corresponding values, e.g., x[i] corresponds to fx[i].

◆ sfixed_func1d_f

template<typename P >
using asgard::sfixed_func1d_f = typedef std::function<void(std::vector<P> const &x, std::vector<P> const &m, std::vector<P> &fx)>

Vector function, computing fx = F(x, f), where f is a field, e.g., moment of the solution.

Represents a single-dimensional function that is "fixed" in time and accepts an additional field parameter.

On entry, the three vectors will have the same size, x will contain the quadrature point values, m will have the additional field values.

On exit, fx[i] must have the value corresponding to x[i] and m[i]

◆ md_func

template<typename P >
using asgard::md_func = typedef std::function<void(P t, vector2d<P> const &x, std::vector<P> &fx)>

Signature for a non-separable function, fx = F(t, x)

Represents a multidimensional function with time-dependence in t, this can be used for either source or initial condition.

On entry, x contains the points so that the i-th point is at (x[i][0], x[i][1], ..., x[i][d]) where d is the number of dimensions and it is equal to x.stride(), see asgard::vector2d

Similarly, fx will have size equal to x.num_strips()

On exit, fx[i] must have the values corresponding to x[i][0] ... x[i][d]

◆ md_func_f

template<typename P >
using asgard::md_func_f = typedef std::function<void(P t, vector2d<P> const &x, std::vector<P> const &f, std::vector<P> &fx)>

Signature for a non-separable function that accepts an additional field parameter.

The signature is the same as asgard::md_func but has an additional field parameter f with size matching x.num_strips() and fx.size()

The function is used to define term coefficient, where f will be values of the field that the term is acting on.

◆ md_mom_func

Signature for a non-separable function with moment dependence.

The signature is the same as asgard::md_func but has an additional moment dependence.

Moments are created by asgard::pde_scheme::register_moment which returns an asgard::moment_id, using the id the vector with values for the moments can be accessed with moment[id].

See BGK example for details.

◆ md_gpu_func

template<typename P >
using asgard::md_gpu_func = typedef std::function<void(int64_t const num, P t, P const x[], P fx[])>

Signature for a GPU non-separable function.

All "gpu" functions require either CUDA or ROCM support and the pointers will reference data on the GPU device.

On entry, num is the number of points and the size of fx, the number of needed since the raw pointers don't have .size()

The length of x is num * num-dims and the i-th point starts from x[i * num_dims].
